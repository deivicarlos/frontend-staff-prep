# Mission: Frontend Senior/Staff Engineering (React + TypeScript)

## Why

Carlos spent the last ~2 years managing rather than shipping. He wants to move back
to the IC track and land a **Senior or Staff Frontend engineer** role. He is employed,
so there is no deadline pressure — but resumes are already going out, which means the
first real interview could land next week or in six months. The job is therefore to be
**continuously interview-ready**, not to peak on a date.

Fullstack roles are the phase-two expansion (he has some Node experience). Frontend
depth comes first: get to genuinely strong there, then widen.

## Success looks like

- Can build a non-trivial React component from scratch in 45 minutes, narrating trade-offs, without reaching for docs on syntax.
- Can run a frontend system design round end to end (RADIO) on prompts like "design a news feed" or "design a design system" and lead the conversation rather than follow it.
- Can answer deep-dive questions on rendering, reconciliation, state ownership, the event loop, and TypeScript generics without hedging.
- Has a current mental model of what changed 2024–2026: React 19, Server Components, React Compiler, the death of manual memoisation, TanStack Query as default server state.
- Has 4–6 staff-level stories ready that convert the management years into an asset (influence, technical strategy, mentoring) rather than a gap to explain.
- Has one substantial public project that survives being read by an interviewer.
- Can debug an unfamiliar, broken multi-component app under a clock, fixing bugs in
  sequence and narrating each fix. This is the format he has actually faced (LR-0012).
- **Security, authentication and authorization, from zero to Staff** (his ask, 2026-10-08):
  can design auth in a system design round and defend it in a Staff discussion, at the level
  of mechanism (browser rules, sessions, tokens, OAuth/OIDC, architectures, authorization).
- Can explain what workers are for, at the level of mechanism.

## Phase 2: engineering with AI

Added 2026-09-24 at his request (LR-0012). Lead and Senior roles now expect engineers who
direct AI agents, not engineers who paste their output. The goal is to separate himself from
vibe coding: controlling context, planning before generating, writing skills, reviewing
generated code against the architecture, and keeping security and design sound. *"AI makes a
good engineer even better but a bad engineer worse."* Starts after the frontend track, which is
what makes this phase work: you can only direct and review what you understand.
One exception, added 2026-09-26: AI-allowed coding is already a round format (Shopify, Canva,
Meta), so AI-allowed timed exercises run inside the frontend track. Phase 2 is the deeper practice.

## Constraints

- Employed full-time. **40–60 minutes a day** is the reliable base (set 2026-09-24), with occasional days off. Every session is self-contained. No multi-session cliffhangers.
- **Located in Canada.** He targets Canada-eligible remote roles at CAD 180k+. Prep is built for Senior loops, with Staff as upside (`career/CAREER.md`).
- Two years since last shipping React. Rust in React, but real voids elsewhere (auth, browser
  security): every lesson starts from zero (rule 2026-10-08, LR-0015).
- Starting point is unmeasured — LR-0001 (the calibration) sets the real floor.

## Also in scope: getting interviews

Added 2026-09-24. The search breaks at the top of the funnel, so resume, LinkedIn, where he
applies, and the "why IC" answer are in scope (`career/CAREER.md`). Salary negotiation is not.

## Out of scope (for now)

- Backend depth beyond what a fullstack screen touches. Revisit once frontend is strong.
- LeetCode-style algorithms as a primary focus. Frontend loops rarely lead with them; revisit only if a target company demands it.
- Accessibility/ARIA as a study track. Real, but screens grade working logic first (LR-0012).
- React Native, mobile, and non-React frameworks (Vue, Svelte, Angular).
