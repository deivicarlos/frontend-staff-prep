When it runs

One interaction, one frame. useLayoutEffect runs before the paint, transitions push work after it, useSyncExternalStore brings outside data in, and React 19's Actions handle the wait for the server.

Lesson 08 · Hooks, part 2 of 2 · ~30 minutes · ← Part 1

1 · The mechanism: what happens between a click and the next frame

The browser has one main thread. While your JS runs, nothing paints. This is the order for one state update (Render and Commit, useLayoutEffect, useEffect):

StepWhat happensPaint blocked?
1 · Event handlerYour onClick runs and calls setStateyes
2 · RenderReact calls the components and works out the differenceyes
3 · CommitReact writes the changes to the DOMyes
4 · useLayoutEffectRuns now. State set here re-renders before the paintyes
5 · PaintThe user sees the new frame. This is where INP stops counting—
6 · useEffectUsually runs here, after the paintno

The precise version of step 6. "If your Effect wasn't caused by an interaction (like a click), React will generally let the browser paint the updated screen first." If it was caused by an interaction, "React may run your Effect before the browser paints" (useEffect). For interviews: "useEffect doesn't block the paint. useLayoutEffect always does."

2 · useLayoutEffect: measure before the user sees it

It exists for one job: read the layout (a size or position) and fix the output before the first paint. The classic case is a tooltip that has to flip above its trigger when there's no room below.

Predict, then reveal

The tooltip renders below, measures its height in an effect, and sets state to move above when it doesn't fit. Using useEffect, what does the user see? What changes with useLayoutEffect, and what does that cost?

With useEffect: a flicker. The browser paints the tooltip below, then the effect's state update moves it above in the next frame.

With useLayoutEffect: no flicker. React "guarantees that the code inside useLayoutEffect and any state updates scheduled inside it will be processed before the browser repaints." The first position never reaches the screen.

The cost: the paint waits for both renders. "When used excessively, this makes your app slow. When possible, prefer useEffect" (useLayoutEffect).

3 · useTransition and useDeferredValue: urgent first, the rest later

Some updates are urgent: the character the user just typed has to appear now. Others aren't, like re-filtering 20,000 rows. Both hooks mark the second kind as interruptible: React renders it in the background and drops it if a newer update arrives. This is the fix for INP's processing phase.

Not a debounce. A debounce waits a fixed delay and then still blocks while it renders. A deferred render has no delay, keeps up with fast devices, and "is interruptible by default" (useDeferredValue, useTransition). Keep debouncing for network calls. A transition makes rendering cheaper; it doesn't reduce requests.

Predict, then reveal

A search input filters a 20,000-row archive table on every keystroke, and typing lags. The input's state and the table are in the same component. Write the fix in three or four lines.

const [query, setQuery] = useState("");
const deferredQuery = useDeferredValue(query);
<input value={query} onChange={(e) => setQuery(e.target.value)} />
<Table query={deferredQuery} />           // Table = memo(...)
{query !== deferredQuery && <Spinner />}

The input renders with the new query straight away. Table still gets the old deferredQuery, so memo skips it. Then React renders the table in the background, and another keystroke restarts that render. You could use useTransition instead, with a second state for the table query set inside startTransition, but never for the input's own state. Virtualizing the table is still the bigger win at 20,000 rows.

4 · useSyncExternalStore: bringing a non-React store into React

Data that lives outside React includes a legacy app's store, a WebSocket cache, and navigator.onLine. When a migration puts React components inside an old app, this is the bridge: React subscribes to the store, reads a snapshot, and renders when the snapshot changes (useSyncExternalStore).

// outside the component, so the function's identity is stable
function subscribe(cb) { return legacyStore.on("change", cb); }   // returns unsubscribe
function getSnapshot() { return legacyStore.getState().selectedId; }

function Inspector() {
  const selectedId = useSyncExternalStore(subscribe, getSnapshot);
}

You've already used it: the request log in exercise 0006 is useSyncExternalStore(log.subscribe, log.get). The two rules:

  • getSnapshot returns the same value while the store hasn't changed, compared with Object.is. Returning a new object every call means "you will enter an infinite loop".
  • subscribe keeps the same identity. Define it outside the component. A new function on every render makes React re-subscribe every time.

Use React state when you can. This hook is "mostly useful if you need to integrate with existing non-React code". In other words, migrations.

Predict, then reveal

What goes wrong here?

const user = useSyncExternalStore(subscribe, () => ({ ...store.user }));

An infinite loop. Every call returns a new object, so React always sees a change. Return store.user itself, provided the store replaces it on change instead of mutating it, or cache the last snapshot and return it until the store changes.

5 · React 19 Actions: waiting on the server

An Action is an async function run inside a transition. React tracks it as pending, and while it runs the UI stays responsive (React 19).

APIWhat it doesThe one rule
useActionState(fn, initial)Returns [state, dispatch, isPending]. fn(prevState, payload) returns the next state. Calls run one after anotherCall dispatch from <form action> or inside startTransition
useOptimistic(value)Shows the expected result immediately while the Action runs, then switches back to the real value when it endsCall the setter inside an Action
use(promise | context)Reads a promise, suspending until it resolves (Suspense shows the fallback). Reads context, and is allowed inside if statementsThe promise must be cached. One created during render "is recreated on every render"

On failure, useOptimistic needs no rollback code. The real value never changed, so the UI "shows what it showed before" (useOptimistic). For a Vite SPA without a framework, TanStack Query still handles server data. These hooks fit forms and mutations (useActionState, use).

6 · Cold check

From memory

List the six steps from a click to useEffect, and mark which ones block the paint. Then: when do you pick useTransition over useDeferredValue?

Handler → render → commit → useLayoutEffect → paint → useEffect. The first four block the paint. useEffect usually runs after it, but may run before it when an interaction caused it.

useTransition when you own the setState call. useDeferredValue when you only receive the value. Neither goes on the input's own state.

Q1 · layout

A popover must measure its own width and clamp to the viewport with no visible jump. Where does the measurement go?

useLayoutEffect. The DOM exists by then and the paint hasn't happened. You can't read refs during render, and useEffect may paint first.
Q2 · deferred

You added useDeferredValue, but typing still lags. The slow list is a plain component. Most likely cause?

No memo. The parent's urgent render renders the list anyway, with the old value, and that's the expensive part.
Q3 · external store

The page freezes with "Maximum update depth exceeded" after you add useSyncExternalStore. The first thing to check is…

getSnapshot. A new object each call means every check looks like a change, so it renders forever.
Q4 · optimistic

The Flag request fails. With useOptimistic, what has to happen to undo the badge?

Nothing. The optimistic value only shows while the Action runs. When it ends, React renders the real value, which never changed. You still show an error message.

Sentence to have ready: "Layout effects run before the paint and block it, so I only use them to measure. For a slow screen I keep the input urgent and push the expensive render into a transition, or defer the value into a memoized child. That targets INP's processing phase. When React sits inside a legacy app, useSyncExternalStore is how React components read the old store without tearing."
